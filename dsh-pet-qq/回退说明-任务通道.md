# 回退方案①（任务队列最小闭环）

一键回到「搭方案①之前」的状态。改动只涉及 2 个被修改文件 + 2 个新增文件，回退脚本会全部还原。

## 改了什么（回退清单）

| 文件 | 类型 | 回退动作 |
|---|---|---|
| `bridge.mjs` | 修改（+import +1 处短路 +TASK 单例） | 从备份还原 |
| `config.json` | 修改（+task 段，默认 false） | 从备份还原 |
| `task-bridge.mjs` | 新增 | 删除 |
| `task-notify.mjs` | 新增 | 删除 |
| `tasks/` | 新增（运行后生成） | 删除 |

备份点：`bridge.mjs.bak-20261120-1010-task1`、`config.json.bak-20261120-1010-task1`

## 方式 A：不删文件，只关开关（最轻，推荐先试）

`config.json` 里 `"task": { "enabled": false }` 就是默认状态。
只要它是 false，桥里的任务钩子永远不命中——**聊天行为与搭建前完全一样**，新增的两个 .mjs 文件只是静静躺着、不被加载。
想彻底移除时再执行方式 B。

## 方式 B：一键回退脚本（还原文件 + 重启桥）

在 PowerShell 里执行（会自动停桥、还原、重启、跑自测）：

```
powershell -NoProfile -ExecutionPolicy Bypass -File "D:/dsh workplace/tools/dsh-pet-qq/rollback-task1.ps1"
```

脚本内容见同目录 `rollback-task1.ps1`。

## 方式 C：手动回退

1. 停桥：`powershell -NoProfile -File stop.ps1`（或按进程名结束 node bridge.mjs）
2. `cp bridge.mjs.bak-20261120-1010-task1 bridge.mjs`
3. `cp config.json.bak-20261120-1010-task1 config.json`
4. 删除 `task-bridge.mjs`、`task-notify.mjs`、`tasks/` 目录
5. 用桌面「一键启动」或 `explorer.exe start-hidden.vbs` 重新起桥
6. `node bridge.mjs --quiet-test` 确认 8/8 通过

## 安全说明

- 搭建全程没有碰正常聊天链路：口令钩子放在 WATCH 之后，只在 `enabled=true` + 白名单 + 私聊 + 明确前缀时才短路，其余消息原样走 `/chat`。
- 回报脚本 `task-notify.mjs` 默认 dry-run，只有显式 `--send` 才真发，且不经过桥本体。
- 所有自测在临时目录进行，不写真实 `tasks/` 队列。
